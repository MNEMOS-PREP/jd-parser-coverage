===============================================================================
  M02 - JD PARSER & COVERAGE PLANNER   ·   REQUIRED KEYS
===============================================================================

  GROQ_API_KEYS   (optional)   one or more comma-separated Groq keys

Optional, and the word is load-bearing. With no key M02 parses every posting
with the deterministic pass alone and says so on the row: `extracted_by` reads
`lexicon (model: no model configured)` rather than the module failing, warning,
or quietly returning less. That is Rule 2 — a missing dependency narrows scope,
never quality, and never silently.

WHERE IT LOOKS
--------------
  1. $AI_KEYS_FILE            an explicit path, for a deployment that mounts a
                              secret somewhere of its own choosing
  2. Backend/keys.txt         this repo
  3. keys.txt                 this repo's root
  4. ../keys.txt              BESIDE the repos, shared by all nineteen modules

The fourth is the one to use in development. Nineteen modules in nineteen
repositories should not mean nineteen copies of the same secret, each a
separate thing to rotate and a separate thing to leak. One file next to the
repos serves all of them, and it cannot be committed by accident because it is
outside every repository.

Environment variables always win over the file, so production sets real
environment variables and ships no file at all.

WHAT THE KEY BUYS
-----------------
One extraction call per UNIQUE posting (FR-2.12 caches the parse by content
hash, so sixty students on one drive pay for one call), against the prose the
deterministic pass cannot read. Measured on the golden corpus:

    lexicon only    precision 0.891   recall 0.826   F1 0.857
    with the model  precision 0.886   recall 0.899   F1 0.892

The model never replaces the lexicon and never adds a requirement the document
does not contain — every proposal must verbatim-resolve to a span or it is
dropped. See `propose.py`.
